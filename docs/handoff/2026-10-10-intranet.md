## 2. 코드 받기(둘 중 이 PC 가 쓰는 방법)
(a) 사내 git 미러가 있으면: `git fetch origin && git merge --ff-only origin/main`. ff 가 안 되면 멈추고 충돌 파일 목록을 보고한다.
(b) 오프라인 번들이면: OPERATIONS.md §2.9 그대로(winmate-src.tar.gz → rsync, app-build.tar.gz 로 web/dist · ops/node_modules 교체).
- **새 서비스 dss(포트 5111)** 가 생겼다(config/services.yaml · services/dss). uv.lock 에는 로컬 패키지 winmate-dss 만 더해졌다(외부 휠 추가 없음)
  → `uv sync --offline --frozen --all-packages` 로 충분하다. npm 의존성은 그대로다.
- 웹은 새 화면이 많으니 web/dist 를 반드시 새로 받는다(번들) — npm 이 되면 `cd web && npm run build`.
- `make contracts-check` 가 통과해야 한다(contracts/dss.json 이 새로 있다). 실패하면 사내망에서 `make contracts` 로 덮어쓰지 말고 보고한다.

## 3. 지식 DB(이미지 검색 · 유관 사례 검색이 안 되던 원인)
원인: kb 가 벡터 모델(winmate-kb/kb/models/*.joblib)을 못 읽으면(다른 파이썬 · scikit-learn 판으로 만든 모델, 깨진 복사, 빠진 파일)
이미지 검색 · 사례 검색(D1) · 메시지 검색(E2)이 500 으로 죽었다. 이제는 키워드 검색으로 내려가고 이유를 보여 준다. 그래도 제대로 고쳐야 한다.
1) `make kb-doctor` → 「고칠 것」 목록을 그대로 따른다. 실패 0 이어야 한다(로컬 이미지 사본 0장 경고는 괜찮다).
2) 「벡터 모델 읽기」가 실패하거나 `/api/_health` 의 kb `search_mode` 가 `keyword_only` 면, 이 PC 의 .venv 파이썬으로 KB 산출물을 다시 만든다:
   `PATH=$PWD/.venv/bin:$PATH bash winmate-kb/build/run_all.sh && (cd winmate-kb && ../.venv/bin/python dashboard/thumb_select.py)`
   (run_all.sh 는 `python3` 를 부른다 — .venv 를 PATH 앞에 두지 않으면 시스템 파이썬의 다른 scikit-learn 으로 모델이 만들어져 kb 가 못 읽는다.)
   빌드 뒤 `git status` 에 winmate-kb/docs/ 변경이 생기면 `git checkout -- winmate-kb/docs/` 로 되돌린다(생성 문서 잡음).
3) `ops/node_modules/.bin/pm2 restart kb` → 10초 뒤 `make kb-doctor` 다시. 기대값(현재 KB 기준):
   - 이미지 검색(로비) 50건 · 사례 검색(호텔 로비 사이니지) 10건 · MagicINFO 메시지 14 · 이미지 11 · 사례 17
   - `/api/_health` kb: `warm=true · search_mode=hybrid · vector_error=null · fts_error=null`
4) 솔루션 매칭 확인(게이트웨이 경유):
   - `/api/kb/v1/images/search?q=로비&limit=6` → 로비 장면 사진이 위에 · `/api/kb/v1/cases/search?q=호텔 로비 사이니지&limit=3` → 3건
   - `/api/kb/v1/solutions/dex` · `/images` · `/cases` → messages 에 `basis=text_match`, images 의 groups 에 `context` 묶음
   - Knox Capture 는 메시지 2건만 나오는 것이 정상(KB 공백 G-SOL-1).

## 6. 화면은 아티팩트 보드를 「철저하게」 따른다 — 폭 · 동적 폭 규칙
디자인 원본은 docs/screens/webapp1/<보드>.dc.html, 그린 결과는 docs/screens/_rendered/webapp1/<보드>.jpg · .txt 다.
claude.ai 아티팩트 링크는 열지 않는다(사내망에서 안 열린다) — 저장소의 보드 파일이 원본이다.
1) 본문 열: 셸이 `.sh-content` 의 직계 자식을 `--wm-main-w`(1180px) 가운데 열로 맞춘다(web/src/shell/shell.css).
   화면 코드에서 `max-width` · `margin: 0 auto` · 고정 width 를 다시 주지 않는다. 1차 개발분에 그런 코드가 있으면 지운다.
2) 고정 칸은 보드 px 그대로(예): RQ1 왼쪽 400 · DSS 공간 270 · CA 목록 290 · 비교 첫 칸 200 · VP 왼쪽 280 · SP 제품 330 · SC 공간 196 · 시나리오 목록 236 ·
   홈 본문 1040 · 흐름 카드 높이 112 · 콘텐츠 카드 118 · 팝업 ProdPicker 760×640 · VpDetail 900×720 · ContentPopup 820×680 · SBPopup 760×660 · JSON 900×780 ·
   SBBar 높이 52 · 저장 버튼 48. 나머지는 `minmax(0, 1fr)`(그냥 `1fr` 은 긴 글자에 칸이 밀린다). flex 자식은 `min-width: 0`.
3) 작업 화면은 높이를 채운다: `FlowScreen`(@/ui) 이 바 · 머리 · 푸터를 뺀 높이를 그리드에 주고, 스크롤은 패널 안에서만. 페이지 전체 스크롤이 생기면 틀린 것이다.
   Gate 는 Storyboard 가 많아도 줄 목록 안에서만 스크롤하고 바닥 줄(목록 · 시작 버튼)은 늘 아래에 있다.
4) 글자 크기 · 둥글기 · 색은 보드 값 → `var(--wm-*)` 토큰. 새 색을 하드코딩하지 않는다(필요하면 docs/requests/platform.md).
5) 공용 부품: `@/shell` 의 ContentListScreen · GateScreen · FlowBar · SBPopup · ContentPopup · FlowDoneView, `@/ui` 의 FlowScreen · FlowHead · AiButton · AiBar ·
   ByTag · KindTag · FlowPanel · FlowFooter · FlowDone · FollowCard · JsonPopup · ProductPickerDialog. 기능 폴더에서 같은 것을 다시 만들지 않는다.
6) 확인 방법(화면마다):
   - 브라우저 1440×900 과 1920×1080 에서 보드 jpg 와 나란히 놓고 본다(보드는 1440×900 기준).
   - 개발자 도구 콘솔에서 폭을 숫자로 잰다: [...document.querySelectorAll('.sh-content > *')].map(e => Math.round(e.getBoundingClientRect().width))   // 1180
   - 보드 .txt 의 글자 순서와 화면 글자 순서가 같은지 본다(라벨 · 버튼 이름 · 빈 상태 문구 그대로).
   - 세로 1~5px 차이는 글꼴 줄 높이 차이일 수 있다(보드 그림은 대체 글꼴). 가로 위치 · 폭 · 상자 높이는 같아야 한다.
   - 다르면 보드가 맞다. 보드와 다르게 해야 하는 이유가 있으면 고치지 말고 보고서에 「보드와 다름: 무엇 · 왜」 로 적는다.
     (이미 정한 차이: services/<x>/AGENTS.md 「새 흐름」 절 — 편집용 조작(×, 연필, 메뉴)은 손을 올렸을 때만 보이게 더함, URL 이 없는 출처는 지어내지 않음 등)
