### 표기

- 백틱 안의 **UI 문구** = 보드 원문 그대로(띄어쓰기·가운뎃점 `·`·화살표·따옴표 포함). 바꾸지 않는다. `{이름}` 같은 중괄호는 데이터가 들어갈 자리다. 예외: **[제안]** 이 붙은 문구, 코드·경로·API 필드, KB 원문 값(이건 KB 그대로).

## 1. 목적과 범위

### 1.1 목적

모든 기능 화면이 공유하는 **틀(셸)**과 **공통 탐색 도구**를 정의한다.

1. 페이지 틀: 왼쪽 사이드바(작업 내역) + 오른쪽 메인(상단 액션바 · [스텝바] · 본문).
2. 홈: 인사 · 기능 진입 카드 10개 · 최근 작업.
3. 상단 액션바의 팝오버 4종(제품 탐색 · 솔루션 탐색 · 이미지 검색 · 유관 사례 검색): 어디서나 열리고, **진행 중인 작업이 있으면** 고른 것을 그 작업에 넣거나 끌어서 놓을 수 있다.
4. 제품·솔루션 상세 시트: 스펙/개요 · 모든 이미지와 출처 메타데이터 · 실제 도입사례 링크.
5. 공통 UI 키트(토큰·컴포넌트)와 공통 컴포넌트(제품 입력창 · 스텝바 · 템플릿 썸네일).

### 1.2 누가 무엇을 가지나

| 영역 | 소유 서비스 / 세션 | 근거 |
|---|---|---|
| 웹 셸 코드 `web/src/shell/**` — 레이아웃, 사이드바, 상단바, 팝오버 4종, 상세 시트, 홈, 공통 UI 키트, ProductInput · Stepper · Thumb 컴포넌트, DnD 기반 | **workspace 세션** | `services.yaml` workspace `owns: [services/workspace/**, web/src/shell/**]` |
| 사용자 · 작업물 색인(사이드바 이력, 홈 최근 작업) · 사용 이력 | **workspace** 서비스 `/api/workspace/v1` | ARCHITECTURE §2, §3 "작업물 색인" |
| 제품 · 카테고리 · 스펙 · 솔루션 · 이미지 · 도입사례 검색과 상세 데이터 | **kb** 서비스 `/api/kb/v1` (winmate-kb 읽기 전용) | ARCHITECTURE §2, §5 |
| 이미지 저장본(로컬 사본)·썸네일 바이너리 | **files** 서비스 (§7.6 갭 G-IMG-2) | ARCHITECTURE §5 "파일 바이너리는 files 서비스만" |
| "내 생성 이미지" 탭 데이터 | **image** 서비스 `/api/image/v1` | services.yaml image |
| `현재 작업에 추가` · `대화에 첨부` · 드롭 처리의 실제 반영 | 현재 화면의 **기능 서비스**(웹 기능 모듈이 셸에 핸들러 등록, §7.5) | ARCHITECTURE §6 기능 모듈 |
| 스텝바의 딸깍 실행 · 제안서 섹션 드롭 영역 | **proposal** (셸은 버튼·팝오버 UI 와 이벤트만) | INDEX: 딸깍·DnD 보드는 proposal |
| 게이트웨이 인증 · `X-User-Id`/`X-User-Name` | gateway | ARCHITECTURE §3 |

- 셸이 kb·workspace·image 계약에 없는 기능이 필요하면 `docs/requests/<service>.md` 에 요청을 적는다(ARCHITECTURE §7). 이 문서 §7 이 그 요청의 초안이다.
- 브라우저는 게이트웨이(`/api/<service>/...`)로만 호출한다. 서비스 포트(5020, 5050 …)에 직접 붙지 않는다.

### 1.3 범위 밖

- 각 기능의 단계 화면(RQ·SB·MI·CA·VP·SP·IMG·BE·SC·PR). 셸은 그 화면들의 틀과 공통 도구만 준다.
- `Guide` 보드(디자인 캔버스 8개 목차)는 실제 앱 화면이 아니다. 구현하지 않는다(§5.13).
- 로그인 화면, 설정 화면(사용자 카드의 설정 버튼 목적지는 §10).

### 3.5 반응형 [제안]

보드는 1440×900 고정이다. 사내 데스크톱 전용으로 보고 다음을 정한다.

- 지원 최소 1280×720. 그 아래는 가로 스크롤.
- 사이드바 260 고정, 메인은 남은 폭(최소 1020). 홈 내용 폭 `min(1040px, 100% - 2×24px)`, 6열 카드는 1040 미만에서 3열.
- 팝오버: 폭은 보드 값, 단 `max-width: calc(100vw - 260px - 32px)`. 높이는 `min(보드 높이, 100vh - 64px - 16px)` 이고 목록 영역만 스크롤.
- 상세 시트: `width: min(1200px, 100vw - 80px)`, `height: min(828px, 100vh - 72px)`, 가운데. 탭 본문은 시트 안에서 세로 스크롤(보드는 `overflow: hidden` — 실제 데이터는 넘칠 수 있다).

#### 5.2.3 진행 중인 작업 맥락

팝오버의 추가·끌기 가능 여부는 현재 화면이 셸에 넘기는 **작업 맥락**으로 정한다(§7.5).

| 값 | 뜻 | 보드 규칙 |
|---|---|---|
| `hasTask` | 진행 중인 작업이 있다 | 명시값이 없으면 `section` 이 있을 때만 true. **홈 = false**, 각 기능의 작업 목록 화면은 false 로 명시(CA0·MI0·VP0·SP0 등) |
| `accepts` | 지금 화면에 그 유형을 받는 **드롭 영역**이 있다(`product`·`solution`·`image`·`case`) | 있을 때만 항목에 끌기 손잡이가 붙는다 |
| `added` | 이미 현재 작업에 들어 있는 항목 | 그 항목 버튼은 `✓ 추가됨`(비활성), 끌 수 없음 |
| `dragItem` | 지금 끌고 있는 항목 | 팝오버 반투명 + 그 항목 점선 |

#### 5.2.4 항목 추가 버튼 상태 (팝오버 4종 공통)

| 상태 | 조건 | 글자 | 스타일 | 활성 | `aria-label` | `title` |
|---|---|---|---|---|---|---|
| `off` | `hasTask=false` | `+ 추가` | 비활성(off) | 아니오 | `추가 {이름}` | `진행 중인 작업이 없어 추가할 수 없습니다` |
| `added` | 항목이 `added` 에 있음 | `✓ 추가됨` | 테두리 `#e9ebef` 바탕 `#f0f2f5` 글자 `#596170` | 아니오 | `추가 {이름}` | `이미 현재 작업에 있습니다` |
| `sel` | 선택 트레이에 있음 | `✓ 선택` | 바탕·테두리 `#1428a0` 흰 글자 | 예(누르면 선택 해제) | `선택 해제 {이름}` | — |
| `add` | 그 밖 | `+ 추가` | 흰 바탕 테두리 `#e2e5ea` 글자 `#1428a0` | 예(누르면 트레이에 넣음) | `추가 {이름}` | — |

- `+ 추가` 는 **바로 넣지 않고 선택 트레이에 담는다.** 실제 반영은 푸터의 `현재 작업에 추가` 한 번으로 한다.
- 선택된 행/카드는 바탕 `#f5f7fd` + 테두리 `#1428a0`(목록 카드) / 이름 `#1428a0`·썸네일 테두리 `#1428a0`(모델 행).

#### 5.2.5 푸터 (팝오버 4종 공통 틀)

- 패딩 `10px 14px`, 위 선 `#e2e5ea`, 바탕 `#fbfbfc`.
- 작업 있음: 왼쪽 `선택 {n}`(12px `#596170`) [+ 유형별 추가 정보] · 오른쪽 `현재 작업에 추가`(h32 패딩 0 12 r8 12.5/600; n>0 이면 primary, n=0 이면 off 스타일 + 비활성).
- 작업 없음: 정보 아이콘 + 안내(12px `#596170` lh 1.45) + 비활성 `현재 작업에 추가`(`title="진행 중인 작업이 없습니다"`).
- `현재 작업에 추가` 를 누르면: 기능 핸들러 `onAdd(type, refs)` 호출 → 성공 시 그 항목들이 `added` 가 되고 트레이를 비운다. 팝오버는 열린 채로 둔다 [제안]. 실패 시 트레이 유지 + 푸터 왼쪽 글을 `추가하지 못했어요. 다시 시도해 주세요.`로 바꾼다 [제안, §10 Q-UI-2].

## 7. 데이터 모델 / API 스케치

### 7.1 공통

- 경로: 서비스 안 `/v1/...`, 브라우저는 게이트웨이 `/api/kb/v1/...` · `/api/workspace/v1/...` · `/api/image/v1/...`.
- 목록: `?limit=&cursor=` → `{"items": [...], "next_cursor": null | "..."}`. 기본 limit 20, 최대 100 [제안].
- 오류: HTTP 상태 + `{"error": {"code": "UPPER_SNAKE", "message": "사람이 읽는 한국어", "details": {}}}`. 쓰는 코드: `NOT_FOUND`(404) · `INVALID_ARGUMENT`(400) · `UNSUPPORTED_FILTER`(400, `details.filters`) · `UPSTREAM_UNAVAILABLE`(503).
- ID: workspace 자원은 ARCHITECTURE 규칙(`<접두사>_<ULID>`). **KB 자원은 KB ID 를 그대로 쓴다**(`top_*` · `cat_*` · `fam_*` · `mdl_*` · `sol_*` · `img_*` · `dep_*` · `kr_*`, DATA_DICTIONARY §0 — 읽기 전용 지식 DB 라 예외). 모델은 경로에서 모델코드(`LH55QMCEBGCXKR`)로도 받는다.
- 시간: ISO 8601 UTC. 화면은 KST 날짜 `YYYY-MM-DD`.
- 숫자: 용량은 바이트 정수로 주고 화면이 포맷한다(§9.2).
- 셸이 쓰는 참조 문자열(ref): `kb:model:mdl_LH55QMCEBGCXKR` · `kb:family:fam_G000182628` · `kb:solution:magicinfo` · `kb:image:img_9ec6148d2e4d9c18` · `kb:case:dep_1490` · `ws:item:<item_id>` · `img:image:<id>`(내 생성) · `custom:<문자열>`(제품 입력창 직접 입력).
- KB 질의 결과 봉투(`decision_hint`, `needs_confirmation` 등, QUERY_COOKBOOK)는 kb 서비스 안에서 쓰고, 화면에 필요한 것만 아래 응답 필드로 옮긴다.

- **X-03** 비활성 버튼은 모두 `title` 로 이유를 보인다.
- **X-04** 끌기 없이 키보드만으로 모든 추가가 된다(`+ 추가` → `현재 작업에 추가`).

### 9.6 출처 · 사용 규칙 (캔버스 메모 `srcRule` 원문 + 보드)

1. `모든 이미지에 출처 페이지 · 원본 파일 URL · 원본 해상도/형식/용량 · 저장본 · 수집일 · 사용 조건 · 사용 이력을 붙인다`
2. `실제 사진은 samsung.com 공식 페이지에서 수집 (2026-10-02) — 목록은 project/data/image_sources.json`
3. `도입사례 사진은 “도입사례 사진” 표기 필수, 대외 사용 범위는 확인 필요로 둔다` — 사례 사진 위에는 항상 배지 `도입사례 사진`.
4. `사례 링크는 실제 페이지 주소, 요약은 원문을 줄여 쓴 것` — 요약 옆에 `요약은 원문을 줄여 쓴 것` 주석.
5. `모델이 일치하는 사례가 없으면 0건이라고 밝히고 “용도 일치” 사례를 따로 표시` — 용도 일치 사례를 제안서에 넣으면 `유사 용도 사례` 로 표기(`제안서에는 '유사 용도 사례'로 표기됩니다`).
6. 사용 조건 문구: 도입사례 `“도입사례 사진” 표기 필수 · 대외 사용 범위 확인 필요`(팝오버) · 공식 이미지 `삼성전자 저작물 · 대외 사용 범위 확인 필요`(시트) · 그 밖 `대외 사용 범위 확인 필요`.
7. 이미지를 작업에 넣거나 대화에 붙이면 출처 메타데이터(ImageMeta)가 함께 간다 — `출처 정보가 함께 붙습니다`.
8. 화면의 이미지는 로컬 저장본만 쓰고, 원본은 `원본 파일`·`원본 열기` 링크로만 연다(오프라인 우선).
9. 모르는 값은 추정하지 않고 `[견적 확인]` 처럼 표시한다(`라이선스 단가 [견적 확인]`).
10. 스펙 값은 원문(`value_raw`) — `값은 원문 그대로`.
